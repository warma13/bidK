# 科技产业园 — "废弃数据中心" 仓库设计文档

## 1. 概述

在现有 **科技产业园** 区域中新增第二种仓库类型 `datacenter`（废弃数据中心），主题为赛博朋克风格。与现有的 `techpark`（AI独角兽总部）形成互补——后者偏向"倒闭科技公司遗物"，而数据中心偏向"未来科技黑市遗物"。

### 定位对比

| 仓库 | 主题 | 风格 | 物品方向 |
|------|------|------|---------|
| AI独角兽总部 (techpark) | 科技创业遗物 | 现代科技 | 服务器、实验设备、办公科技 |
| **废弃数据中心 (datacenter)** | 赛博朋克黑市 | 近未来/霓虹暗黑 | 义体改装件、黑客装备、街头科技 |

---

## 2. 仓库类型配置

当前生成算法是**填充率驱动**的：以 50% 为中位数的正态分布采样 `fillRate`，再乘以总格子数得到 `targetCells`，循环放入物品直到占满目标格子。物品数量是放置结果，不是输入参数。

仓库类型只需提供 `sizeWeights`（控制大小件出现比例），`expectedValue` 来自难度配置。

```lua
datacenter = {
    name = "废弃数据中心",
    icon = "image/warehouse_datacenter.png",  -- 需要生成
    sizeWeights = { 20, 25, 25, 18, 12 },
    -- 对比 techpark: { 25, 25, 25, 15, 10 }
    -- 大件(6格+/9格+)权重更高，体现服务器机柜、义体存储舱等大型设备
}
```

### sizeWeights 对比

`sizeWeights` 对应 `{ 1格, 2格, 4格, 6格, 9格+ }` 五个尺寸档位：

| 尺寸档 | 杂货铺 | AI独角兽总部 | 废弃数据中心 | 效果 |
|--------|--------|-------------|-------------|------|
| 1格 (1x1) | 35 | 25 | 20 | 小件更少 |
| 2格 (2x1/1x2) | 30 | 25 | 25 | 持平 |
| 4格 (2x2) | 20 | 25 | 25 | 持平 |
| 6格 (3x2/2x3) | 10 | 15 | 18 | 中大件更多 |
| 9格+ (3x3~5x5) | 5 | 10 | 12 | 巨型件更多 |

设计意图：数据中心里有大量服务器机柜、液冷塔、量子计算柜等大型设备，小件零散配件相对少。

---

## 3. 区域配置变更

在科技产业园的 `warehouseTypes` 中加入 `datacenter`：

```lua
{
    id = "techpark", name = "科技产业园",
    warehouseTypes = { "techpark", "datacenter" },  -- 新增
    difficulties = {
        -- 保持现有难度不变
        { level = "hard",      label = "50万场",  ... },
        { level = "nightmare", label = "200万场", ... },
    },
}
```

进入科技产业园后，仓库会从 `techpark` 和 `datacenter` 两种类型中随机生成。

## 4. 物品池设计

### 4.1 设计原则

- 灵感来源：赛博朋克近未来科幻题材（义体改造、黑客文化、霓虹街头）
- **所有名称均为原创**，不直接使用任何版权作品的专有名词
- 覆盖现有 7 个品类（能源、交通、艺术、科技、古董、珠宝、机械）
- 每个品类有对应的赛博朋克解读

### 4.2 品类赛博朋克化映射

| 原始品类 | 赛博朋克解读 | 物品方向 |
|---------|-------------|---------|
| 能源 energy | 核心能源模块 | 微型反应堆、生物电池、量子能源核心 |
| 交通 transport | 载具改装件 | 反重力引擎、飞行摩托零件、磁悬浮组件 |
| 艺术 art | 数字艺术/街头文化 | 全息投影画、AI生成画原版、霓虹灯管艺术 |
| 科技 tech | 黑客装备/初代遗物/义体饰品 | 神经接口、量子解密器、初代VR头显、比特矿机、钛合金义眼、液态金属戒指 |
| 机械 mechanical | 义体改装件 | 机械臂框架、动力外骨骼、液压关节组 |

### 4.3 物品池存放位置

仓库生成器通过独立模块加载物品池，每种仓库类型对应一个文件：

```
scripts/Config/Warehouses/
├── ItemPool.lua    ← grocery / techpark 共用
├── Repair.lua      ← 老修理铺
├── Storage.lua     ← 居民储物间
└── DataCenter.lua  ← 🆕 废弃数据中心（需新建）
```

每个模块包含若干品类（category），每个品类 29 件物品，固定稀有度分布：

| 稀有度 | 数量 |
|--------|------|
| white | 10 |
| green | 8 |
| blue | 5 |
| purple | 3 |
| gold | 2 |
| red | 1 |

新仓库需要创建 `DataCenter.lua`，注册到 `WarehouseGenerator.lua` 的 `warehouseModules` 表中。

> **注意**：`Config.ITEMS` 和 `Config.WHITE_ITEMS` 与仓库生成无关，也不是揭示系统的数据源。揭示系统（RevealPlanner + InfoSystem）使用的是**运行时生成的仓库物品**（通过 `InfoSystem.Init(warehouseItems, ...)` 传入）。AI 池均价由 `EstimateValue.GetPoolAverage(whTypeId)` 动态计算，按当前仓库类型的物品池模块和品类权重加权，不使用 `Config.ITEMS`。以下物品设计都是针对 `DataCenter.lua` 模块。

共计 **145 件物品**（5 品类 x 29 件）。上文 4.4 / 4.5 节列出的是各品类的代表性设计方向和部分高稀有度物品，实际实现时需补全至每品类 29 件。

## 6. 价值体系设计

### 现有物品池价值参考

现有物品池（`ItemPool.lua`）每个品类 29 件，已包含全部 6 个稀有度（含红色）。红色物品价值在 850万 ~ 2500万 之间。

### 赛博朋克物品价值定位

本设计文档中的彩色物品基础价值（2,000 ~ 50,000）是**初步设计值**，实际实现时需要参照现有物品池的价值量级进行调整，确保在同难度下经济平衡。

## 7. 难度适配

仓库生成器使用 `budgetWeight` 函数按预算目标动态调整物品选取权重：价值越接近预算目标的物品被选中概率越高（高斯权重 `exp(-1.5 × ln(value/target)²)`），同时乘以品类权重 `categoryWeights`。

不同难度通过 `expectedValue`（区域期望值）和 `budgetPerPick`（单件预算目标）间接控制稀有度分布：

| 难度 | expectedValue | 效果 |
|------|--------------|------|
| 50万场 | 较低 | 单件预算低，自然偏向低价值物品（white/green 为主） |
| 200万场 | 较高 | 单件预算高，高价值物品（purple/gold/red）被选中概率提升 |

> **注意**：Config 难度配置中定义了 `rarityWeights` 字段，但仓库生成器实际未使用该字段，物品选取完全由 `budgetWeight × categoryWeight` 驱动。

## 9. 实施步骤

1. **新建物品池模块**：
   - 创建 `scripts/Config/Warehouses/DataCenter.lua`
   - 按现有模块格式（参考 `ItemPool.lua`）定义品类和物品
   - 每品类 29 件，稀有度分布 white10 / green8 / blue5 / purple3 / gold2 / red1

2. **WarehouseGenerator.lua 改动**：
   - 在 `warehouseModules` 表中注册 `datacenter = "Config.Warehouses.DataCenter"`

3. **Config.lua 改动**：
   - 在 `WAREHOUSE_TYPES` 中新增 `datacenter` 类型（只需 `name` + `sizeWeights`）
   - 在科技产业园 region 的 `warehouseTypes` 加入 `"datacenter"`

4. **美术资源**：
   - 生成仓库图标 `warehouse_datacenter.png`
   - （可选）生成仓库背景图
   - （可选）为新物品生成 icon

5. **测试验证**：
   - 进入科技产业园，确认两种仓库类型都能生成
   - 验证物品分布符合 rarityWeights
   - 验证大件物品能正确放入仓库格子
   - 验证揭示系统对新物品正常工作
